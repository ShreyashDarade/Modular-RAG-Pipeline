# ADR 0004: Wire contract package and the use-case layer

Status: accepted

**Context.** Request/response models lived in `src/api/schemas.py` next to the routes, and the orchestration of
each use case lived in the route functions. An SDK that embeds the pipeline would have to copy that logic, and
the two copies would drift.

**Decision.** (1) `src/contracts` holds the wire models (pydantic only) and is shared by the API and the SDK.
(2) `src/application.RagService` implements every use case once and returns contract models; HTTP routes and the
embedded SDK are thin adapters over it. (3) `docs/openapi.json` is checked in and regenerated by a script; a test
fails on any difference. (4) Within `/api/v1` changes are additive only. (5) Error codes are contract.
`IngestResponse.status_url` becomes optional (it is an HTTP concern; the embedded engine has no URL).

**Consequences.** Routes shrink to HTTP translation (status codes, headers, SSE framing, rate limiting).
The CLI and MCP server still call the container directly; they migrate incrementally and new use cases must not
follow their example.

**Enforced by.** Layering contracts; OpenAPI snapshot; parity suite.
